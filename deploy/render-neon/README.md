# استضافة سايح مجاناً: Render + Neon

دليل تشغيل المتجر مجاناً بالكامل، بدون بطاقة دولية، وبدون اعتماد على كهرباء أو نت البيت. مناسب تماماً لمرحلة التجربة الحالية — بعد ما ثبت إن الكهرباء والنت عندك ينقطعوا، خيار البيت طلع من الحساب نهائياً، وهذا البديل المجاني الوحيد اللي ما يحتاج بطاقة.

**الفكرة:** خادمين منفصلين، كل واحد بيسوي شغلته لحاله:
- **Neon** يستضيف قاعدة PostgreSQL — مجاني دائم، بدون بطاقة، بيانات ما تُحذف أبداً.
- **Render** يستضيف الـ backend (الـ API) ولوحة الأدمن — مجاني، بدون بطاقة.

**ليش خادمين منفصلين ومو خادم واحد يسوي كل شيء؟** لأن قاعدة بيانات Render المجانية **تُحذف تلقائياً بعد ٣٠ يوم**. محفظتك وطلباتك ما تتحمل هذا. Neon قاعدته المجانية **دائمة، بدون حد زمني**.

---

## قبل ما تبدأ

**تحتاج:**
- حساب GitHub (تسجّل فيه المستودع أصلاً)
- بريد إلكتروني للتسجيل في Neon وRender (يقبلوا تسجيل دخول بحساب GitHub مباشرة، أسهل)

**ما تحتاج:** بطاقة دولية، ولا جهاز يقعد شغّال، ولا WSL.

**العيب الوحيد الصادق:** خدمة Render المجانية "تنام" بعد ١٥ دقيقة خمول، وتصحى بحوالي دقيقة عند أول طلب بعدها. يعني أول زبون يفتح التطبيق بعد فترة هدوء يستنى دقيقة تقريباً. لوحة الأدمن (موقع ثابت) **ما تنام أبداً** — هذا العيب يخص الـ API بس.

---

## الخطوة ١: أنشئ قاعدة البيانات على Neon

1. روح [neon.com](https://neon.com) وسجّل دخول بحساب GitHub — بدون بطاقة.
2. أنشئ مشروع جديد (Project)، اختر أقرب منطقة جغرافية متاحة (أوروبا أفضل من أمريكا لتقليل التأخير من ليبيا).
3. من لوحة المشروع، انسخ **رابط الاتصال (Connection String)** — يبدأ بـ `postgresql://...`. Neon يعطيك نوعين: **Pooled connection** و**Direct connection**. **خذ الـ Pooled** (يحتوي `-pooler` في اسم المضيف) — أنسب لخدمة زي Render اللي تعيد الاتصال كل ما تصحى من النوم.
4. احفظ الرابط — بتحتاجه في الخطوة الجاية. فيه بالفعل `?sslmode=require` بآخره، لا تشيله.

---

## الخطوة ٢: انشر على Render

المستودع فيه ملف `render.yaml` جاهز (Blueprint) يوصف الخدمتين معاً.

1. روح [render.com](https://render.com) وسجّل دخول بحساب GitHub.
2. من اللوحة الرئيسية: **New → Blueprint**.
3. اختر مستودع `App`، وفرع `claude/app-plan-4fv8ik`.
4. Render يقرأ `render.yaml` تلقائياً ويعرض عليك خدمتين: `sayeh-api` و`sayeh-admin`. اضغط **Apply**.
5. راح يطلب منك القيم اللي علّمناها `sync: false` (يعني ما نحطها في الكود لأنها أسرار). املأها:

| المتغيّر | شنو تحط |
|---|---|
| `DATABASE_URL` | رابط Neon الـ **Pooled** من الخطوة ١ |
| `SEED_ADMIN_EMAIL` | إيميلك للدخول للوحة الأدمن |
| `SEED_ADMIN_PASSWORD` | كلمة سر قوية (١٢ حرف فأكثر) |
| `SUPPORT_WHATSAPP` | رقمك بصيغة دولية بدون `+`، مثال `218912345678` |
| `SMS_GATEWAY_URL` | اتركها فاضية الآن — التفصيل تحت |
| `LIBYA_PLAY_API_KEY` / `LIBYA_PLAY_EMAIL` / `PLUS_API_KEY` / `PLUS_USD_TO_LYD_RATE` | اتركها فاضية لو ما عندك مفاتيح الموردين بعد — التطبيق يشتغل بدونها، بس المزامنة مع الموردين الحقيقيين ما تشتغل لحد ما تحطها |

6. اضغط **Deploy Blueprint**. Render يبني الخدمتين، يشغّل الـ migrations تلقائياً كأول خطوة عند بدء تشغيل الـ API (الخطة المجانية ما تدعم `preDeployCommand`)، وينشر.

بعد دقيقة ولا دقيقتين، رابطك يكون جاهز:
```
https://sayeh-api.onrender.com        ← الـ API
https://sayeh-admin.onrender.com      ← لوحة الأدمن
```

## الخطوة ٣: أنشئ حساب الأدمن

هذا الجزء ما يقدر يصير من داخل لوحة Render — **الخطة المجانية ما فيها وصول Shell** لتشغيل أوامر مباشرة على الخادم. الحل: تشغّل سكربت `seed:admin` من جهازك، وهو يتصل بقاعدة Neon مباشرة (بيانات الاتصال نفسها، مش محتاج Render إطلاقاً في هذي الخطوة).

**ما تحتاج WSL لهذا.** تحميل Node.js العادي لويندوز أبسط بكثير:

1. حمّل Node.js LTS من [nodejs.org](https://nodejs.org) (ملف `.msi` عادي، تثبيت عادي بالكامل — بدون أي درامز DISM أو PowerShell).
2. افتح PowerShell عادي (مو كمسؤول، ما يحتاج):
   ```powershell
   git clone --branch claude/app-plan-4fv8ik https://github.com/<owner>/App.git
   cd App\backend
   npm install
   ```
3. شغّل سكربت الزرع بمتغيرات الاتصال بقاعدة Neon الحقيقية:
   ```powershell
   $env:DATABASE_URL="رابط-Neon-Pooled-هنا"
   $env:SEED_ADMIN_EMAIL="بريدك@example.com"
   $env:SEED_ADMIN_PASSWORD="نفس-كلمة-السر-اللي-حطيتها-في-Render"
   npm run seed:admin
   ```

لازم `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD` هنا يطابقوا بالضبط اللي حطيتهم في Render وقت النشر، وإلا يصير عندك حساب أدمن بكلمة سر مختلفة عن اللي في `.env` وتتلخبط.

سجّل دخول على `https://sayeh-admin.onrender.com` — لازم تشوف لوحة الأدمن.

## الخطوة ٤: ابنِ التطبيق على العنوان الجديد

```bash
cd mobile
flutter build apk --release --dart-define=API_BASE_URL=https://sayeh-api.onrender.com/api/v1
```

الملف يطلع في `build/app/outputs/flutter-apk/app-release.apk` — هذا اللي تنشره لأول مستخدمين تجربونهم.

## قرار مهم: رموز التحقق (OTP) الآن مش بترسل فعلياً

`SMS_GATEWAY_URL` تركناها فاضية عمداً. بدونها، رمز التحقق (٦ أرقام) **يُطبع في سجل Render بدل ما يُرسل SMS فعلي**. هذا مقبول تماماً لمرحلة "أجرّبه مع ٢-٣ أصدقاء أعرفهم" — أنت تفتح سجل Render، تشوف الرمز، وتقوله لصاحبك بالهاتف أو واتساب.

**كيف تشوف الرمز:**
1. من لوحة Render → خدمة `sayeh-api` → تبويب **Logs**.
2. دوّر على سطر فيه `[sms:console]` — فيه الرقم والرمز.

**متى تحتاج بوابة SMS حقيقية؟** لما تقرر تطلق فعلياً لناس ما تعرفهم شخصياً. وقتها بوابات زي تطبيقات SMS Gateway على أندرويد (تستخدم شريحتك نفسها لإرسال رسائل حقيقية عبر API) هي الحل الشائع في غياب مزود SMS تجاري في ليبيا. قولي وقتها وأساعدك تربطها.

## التحقق من عدد الوسطاء (نفس المبدأ اللي شرحناه لخيار البيت)

`TRUST_PROXY_HOPS=1` مضبوط في `render.yaml` — Render نفسه وسيط واحد بين الزبون وتطبيقك (نفس نمط أغلب منصات الاستضافة السحابية). للتأكد الفعلي، استخدم نفس طريقة `deploy/home/README.md`: افتح التطبيق من تلفونين مختلفين على بيانات جوال (مش واي فاي)، وتابع ترويسة `X-RateLimit-Remaining` في كل طلب — لو كل تلفون له عداد منفصل، الرقم صحيح.

## التشغيل اليومي

```bash
# سجل الأخطاء المباشر
لوحة Render → sayeh-api → Logs

# تحديث لآخر نسخة من الكود
git push origin claude/app-plan-4fv8ik
# Render ينشر تلقائياً عند كل push (Auto-Deploy مفعّل افتراضياً)
```

**النسخ الاحتياطي:** Neon يحتفظ بنقاط استعادة تلقائية (Point-in-time restore) في خطته المجانية لعدة أيام للخلف — تقدر تسترجع منها من لوحة Neon مباشرة بدون سكربت خاص، بعكس إعداد VPS اللي بنيناه.

## متى تنتقل لخيار مدفوع؟

لما تبدأ تخسر زبائن بسبب دقيقة الانتظار وقت الاستيقاظ من النوم، أو يصير عندك دخل يغطي تكلفة خطة مدفوعة. النقل من Neon سهل — أي استضافة PostgreSQL تانية تقبل استيراد `pg_dump` عادي، ما تحتاج تعيد بناء شيء من الصفر.
